# Trilho — Data tables (report)

_Source: `db/schema.ts` · Postgres (Neon). See `docs/data-model.md` for the ER diagram and delete behaviour._

Column names are `snake_case`. Trilho tables use `uuid` primary keys with default `gen_random_uuid()`; the Better Auth tables (including `user`) use `text` ids generated by Better Auth. `timestamptz` = `timestamp with time zone`. Foreign keys have no `ON UPDATE` action (Postgres default `NO ACTION`).

**Enums:** `user_role` (`student`, `career_service`) · `application_status` (`sent`, `in_process`, `interview`, `offer`, `rejected`, `no_response`) · `reminder_reason` (`company_median`, `fallback_14_days`) · `reminder_outcome` (`followup_done`, `dismissed`) · `event_name` (`application_form_opened`, `application_created`, `reminder_triggered`, `reminder_followup_done`, `reminder_dismissed`).

## Better Auth tables

`session` stores login sessions; `account` stores credentials (the password hash); `verification` stores email-verification tokens. All have `created_at` and `updated_at` (timestamptz, not null, default `now()`).

| Table | PK | FK | Other attributes and constraints |
|---|---|---|---|
| `session` | `id` text | `user_id` text → `user.id` (not null, on delete cascade, indexed) | `token` text not null unique; `expires_at` timestamptz not null; `ip_address`, `user_agent` text nullable |
| `account` | `id` text | `user_id` text → `user.id` (not null, on delete cascade, indexed) | `account_id`, `provider_id` text not null; `password` text nullable (hash); `access_token`, `refresh_token`, `id_token`, `scope` text nullable; `access_token_expires_at`, `refresh_token_expires_at` timestamptz nullable |
| `verification` | `id` text | — | `identifier` text not null (indexed); `value` text not null; `expires_at` timestamptz not null |
